Папка аудита действий Codex: по одному markdown-файлу на действие, плюс INDEX.md для маппинга задач (если заказчик даёт номер).
Каждый аудит: Цель → Контекст → План → Изменения → Решения/обоснования → Риски → Следующие шаги, с DoD и мини-ревью.
Перед созданием нового аудита: перечислить `docs/codex/`, проверить уникальность timestamp и только затем записывать файл.
Для инцидентов доступа фиксировать в аудите клиентские логи (код HTTP, endpoint, параметры запроса) и предполагаемый слой причины (клиент/сервер).
