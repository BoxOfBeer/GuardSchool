# Изменения (по файлам)
## PR-блок 1: Runtime-совместимость экрана
- `static/screen.js`
  - Добавлена функция `gsQueryParams(...)` с fallback, если `URLSearchParams` недоступен.
  - Заменены ключевые точки чтения query-параметров на `gsQueryParams`.
  - Усилен `fetchScreenPayload`: fallback на `XMLHttpRequest`, если `fetch`/`AbortController` недоступны.

Зачем:
- старые ТВ/телефоны часто не имеют полного набора web API, но могут работать через XHR и простое разбор query-строки;
- снизить вероятность «белого экрана» из-за раннего runtime-crash.

## PR-блок 2: Док-синхрон и навигация
- `static/agents.txt` — добавлено описание каталога статических ресурсов.
- `agents.txt` — обновлён фокус текущего этапа стабилизации.

# Решения / обоснования
1. Выбран путь graceful fallback вместо полного переписывания в ES5, чтобы не рисковать регрессией всего рендера.
2. Сохранён контракт `fetchScreenPayload` (ожидаемые поля `ok/status/json/text`) для минимальной инвазивности.
3. Логика параметров (`gs_mobile`, `gs_classes`, `gs_mw`, `gs_tv_token`, `gs_reset`) сохранена без изменений поведения.

# Риски
- Скрипт всё ещё использует ES6+ синтаксис; для совсем старых движков без поддержки `let/const/async` требуется отдельный legacy-бандл.
- XHR fallback покрывает загрузку payload, но не решает ограничения очень старых TLS-стеков на стороне устройства.
