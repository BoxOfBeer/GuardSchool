# Цель
Реализовать функцию «Обратная связь» для мобильного экрана: кнопка 💬, форма отправки, антиспам 1/5 мин по device_hash, хранение и админ‑просмотр с действиями.

# Контекст
Входные данные: задача №4 (feedback), существующая архитектура FastAPI + статический UI.
Ограничения: не ломать текущий mobile_mode и шестерёнку, хранение в серверном слое.
Ожидаемый артефакт: backend API + хранение сообщений + UI на экране и в админке.

# План
1. Добавить серверное хранилище feedback_messages и операции (create/list/hide/read/block).
2. Включить флаг экрана enable_feedback в конфиге и админской форме.
3. Добавить кнопку 💬 и форму отправки на screen при mobile_mode + enable_feedback.
4. Добавить блок «Обратная связь» в админке и действия по сообщениям.
5. Проверить сборку Python/JS и зафиксировать изменения.

# Решения/обоснования
- Хранение реализовано через SQLite, чтобы обеспечить «табличный» формат feedback_messages в локальном режиме без внешней БД.
- Антиспам проверяется на сервере (истинный источник), клиент показывает ответ сервера.
- Кнопка feedback показана только в mobile_mode и при enable_feedback=true, чтобы не менять ТВ‑сценарий.
- Админские действия read/hide/block вынесены в отдельные POST API для простого контроля и минимального UI‑риска.

# Риски
- Для SaaS-мультиарендности tenant_id сейчас берётся из cookie (fallback local); при расширении SaaS может понадобиться более строгая привязка tenant.
- Временные метки в SQLite хранятся ISO-строкой UTC; при аналитике по TZ потребуется преобразование в UI.
