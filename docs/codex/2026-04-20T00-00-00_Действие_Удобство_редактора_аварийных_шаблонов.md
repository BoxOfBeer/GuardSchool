# Цель
Сделать редактор «Шаблоны при глобальном аварийном режиме» удобнее: убрать эффект растяжения на всю доступную ширину и сделать выбор шаблона для редактирования более заметным (выпадающий список в верхней панели редактора).

# Контекст
- Входные данные: запрос заказчика на улучшение UX редактора аварийных шаблонов.
- Ограничения: не менять бизнес-логику, только UI-связку и отображение.
- Ожидаемый артефакт: правки `static/app.js` и `static/styles.css` + проверка синтаксиса JS.

# План
1. Найти текущую разметку редактора аварийных шаблонов и место выбора шаблона.
2. Перестроить HTML-структуру редактора: явный блок с выпадающим списком выбора шаблона.
3. Добавить CSS-ограничение ширины/центрирование и компактную сетку полей.
4. Запустить проверку синтаксиса и зафиксировать изменения.

# Изменения (по файлам)
- `static/app.js`: переработан HTML-шаблон `renderEmergencyTemplatesAdmin()` — добавлена верхняя панель редактора (`emergency-editor-toolbar`) с заметным `select` выбора шаблона и группой действий; добавлены семантические CSS-классы вместо inline-стилей части макета.
- `static/styles.css`: добавлены стили для нового контейнера редактора (`emergency-editor-shell`) с ограничением ширины, центрированием, сеткой параметров и выравниванием панели выбора.

# Решения/обоснования
- Выбор шаблона уже существовал, но визуально терялся среди полей; вынесен в первую строку редактора рядом с кнопками действий.
- Для «без растяжения на весь экран» добавлен ограниченный контейнер ширины (`max-width`) с внутренним фоном/рамкой: фокус на форме и меньше визуального шума.
- Бизнес-логика сохранения/переключения шаблонов не менялась; изменена только структура и стили UI.

# Риски
- Возможны точечные различия отображения на очень узких экранах; компенсировано `flex-wrap` и адаптивной `grid`-схемой.
- Так как часть инлайн-стилей заменена классами, при сторонних переопределениях CSS может понадобиться корректировка специфичности.
