# Цель
Добавить в аварийные шаблоны опциональный таймер обратного отсчёта (`timer_seconds`) с отображением на аварийном оверлее и настройкой в админке.

# Контекст
- Входные данные: запрос на расширение аварийного режима таймером без автодеактивации режима при достижении `00:00`.
- Ограничения: сохранить текущую архитектуру (экран = набор виджетов; поведение через конфиг; без жёсткой привязки к устройству).
- Ожидаемый артефакт: изменения в backend-санации конфигурации, админ-редакторе шаблонов, TV-render логике и локализациях.

# План
1. Расширить backend-санацию аварийных шаблонов и подстановку шаблона в экран значением `timer_seconds`.
2. Добавить поле `Таймер (секунды)` в админ-редактор аварийных шаблонов.
3. Реализовать вывод и тикер таймера на аварийном виджете (с остановкой на `00:00`, без отключения режима).
4. Добавить локализационные ключи и стили под блок таймера.
5. Прогнать точечные проверки синтаксиса/диффа.

# Решения/обоснования
- Таймер хранится в конфиге шаблона (`settings.timer_seconds`), чтобы поведение определялось конфигурацией, а не типом устройства.
- Обновление таймера вынесено в отдельный 1-секундный UI-тик (через `data-seconds-left`), чтобы не требовать полного poll/перерендера каждую секунду.
- При `0` таймер не показывается; при `>0` показывается и фиксируется на `00:00` по достижении конца.
- Автоотключение аварийного режима не реализовано намеренно (по требованию).

# Риски
- При нестандартных длительных «заморозках» вкладки браузер может пропускать шаги `setInterval`; фактическое время корректируется при следующем полном render из `deadline`.
- При изменении шаблона во время активного режима countdown перезапускается (идентификатор состояния учитывает контент/таймер шаблона).

- Альтернатива 1: считать таймер на сервере и отдавать «остаток» в API каждый poll.

  Отклонено: лишняя нагрузка/мигания, хуже для слабых ТВ-браузеров.
