# Цель
Стабилизировать реализацию «Новости школы» после слияний: устранить конфликтные места в разметке/доступе к данным и закрыть замечания по безопасности публичного контента.

# Контекст
- Входные данные, ограничения, ожидаемый артефакт: пользователь сообщил о конфликтах после обновлений/слияний; требуется обновлённый рабочий код без поломок в админке и публичном API.
- Ограничения: текущая архитектура репозитория (FastAPI + статический фронтенд), без отдельного генератора QR на backend.
- Ожидаемый артефакт: корректная разметка секций, безопаснее санитизация контента, публичный доступ только к активным новостям.

# План
1. Проверить текущие артефакты и потенциальные конфликтные зоны.
2. Исправить backend-логику новостей (санитизация/доступность).
3. Исправить конфликт разметки в админке (уникальные aria/id).
4. Обновить agents и зафиксировать аудит/проверки.

# Изменения (по файлам)
- `guardschool/app.py`:
  - усилена санитизация HTML новости (удаление `<script>` и inline-событий);
  - публичный endpoint `/api/school-news/{id}` ограничен только активными новостями.
- `static/index.html`:
  - устранён конфликт `aria-labelledby`/id: для блока новостей введён отдельный `school-news-title`.
- `static/admin/state.js`:
  - синхронизирован id поля заголовка (`school-news-title-input`) после устранения коллизии id в разметке.
- `static/agents.txt`:
  - добавлено правило проверки конфликтов id/aria и связок state↔DOM после слияний.
- `guardschool/agents.txt`:
  - дополнено требование по санитизации HTML и публичной выдаче только активных сущностей.

# Решения/обоснования
- Конфликт одинакового `aria-labelledby` в соседних секциях после merge мог приводить к некорректной доступности/сопровождению формы; выделен отдельный идентификатор.
- Публичная выдача неактивной новости нежелательна для административных черновиков; ограничение добавлено на уровне API.
- Базовая фильтрация скриптов и inline-обработчиков снижает риск XSS в публичной странице новости.

# Риски
- Regex-санитизация не равна полноценному HTML sanitizer (возможны экзотические payload).
- Для строгой защиты в будущем лучше использовать whitelist sanitizer на backend.
