# Цель
Убрать риск ручных ошибок при пересечении веток `rss_news` и `school_news`: сделать совместимость двух типов виджетов и добавить автоматическую проверку merge-маркеров.

# Контекст
- Входные данные, ограничения, ожидаемый артефакт: пользователь видит конфликтные фрагменты `<<<<<<<` и боится ручной правки в большом наборе файлов.
- Ограничения: сохранить текущую архитектуру, не ломать существующий `school_news`, не удалять потенциальный `rss_news` из соседней ветки.
- Ожидаемый артефакт: код, где оба типа виджетов сосуществуют без конфликтов, плюс скрипт-проверка на маркеры слияния.

# План
1. Расширить backend и frontend на совместимость с `rss_news`.
2. Добавить автоматическую проверку merge-маркеров в репозитории.
3. Прогнать smoke-проверки синтаксиса и отсутствие конфликтных маркеров.

# Решения/обоснования
- Вместо ручного выбора «или rss, или school news» реализована совместимость обоих типов в одном коде — это снижает вероятность регресса при следующих merge.
- Добавление отдельного скрипта проверки маркеров позволяет автоматически ловить такие проблемы до ручного тестирования.

# Риски
- `rss_news` сейчас совместимостный (пустой источник по умолчанию); для реального RSS нужен отдельный источник данных.
- При дальнейших merge важно запускать `scripts/check_merge_markers.py` в CI/локальной проверке.
