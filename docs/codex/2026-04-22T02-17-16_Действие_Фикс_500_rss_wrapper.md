# Цель
Устранить HTTP 500 на `/api/screen/{slug}` и `/api/admin/preview-payload`, вызванный конфликтом реализации `load_rss_news` после merge.

# Контекст
- Входные данные: логи клиента с `500 Internal Server Error` для `GET /api/screen/mobil` и `POST /api/admin/preview-payload`.
- Ограничения: не менять UI-бизнес-логику, исправить проблему в backend-оркестрации.
- Ожидаемый артефакт: backend возвращает payload экрана/превью без падения, `rss_news` грузится через `gs_rss_news`.

# План

4. Прогнать синтаксис Python/JS и проверку merge-маркеров.
5. Обновить `agents.txt` и зафиксировать аудит.

# Решения/обоснования
- Причина 500: в `app.py` после merge была переопределена импортированная `load_rss_news` функцией-заглушкой без аргументов, а код вызывал её как `load_rss_news(cfg)` и `load_rss_news(cfg, force_refresh=True)`.
- Исправление выполнено в слое backend orchestration, без изменений UI.
- Дополнительно очищены дубли ключей в payload, чтобы избежать неявного перезаписывания и будущих регрессий.

# Риски
- Если внешние RSS-источники недоступны, список `rss_news` может быть пустым, но это уже штатный fallback сервиса.
- Возможны скрытые вызовы `load_rss_news` в других модулях; в текущем scope проверен `guardschool/app.py`.
