# Цель
Устранить повторяющиеся 403 на `/api/screen/{slug}` после обновления, сделав восстановление Bearer-токена экрана устойчивым на устройствах с нестабильным `localStorage`.

# Контекст
- Входные данные: логи браузера с `GET /api/screen/mobil ... 403 (Forbidden)` в цикле refresh.
- Ограничения: не переносить бизнес-логику в UI, не менять серверный контракт API, сохранить совместимость старых ТВ-браузеров.
- Ожидаемый артефакт: клиент `static/screen.js` должен брать Bearer не только из `localStorage`, но и из URL-параметра `gs_tv_token` как fallback.

# План
1. Проверить путь построения Authorization в `static/screen.js`.
2. Добавить fallback-чтение `gs_tv_token` из URL и in-memory cache токена.
3. Убрать раннее удаление `gs_tv_token` из URL, чтобы не терять токен при проблемах storage.
4. Прогнать синтаксические проверки JS и проверку merge-маркеров.
5. Обновить `agents.txt` и зафиксировать аудит.

# Изменения (по файлам)
- `static/screen.js`:
  - добавлена функция `getGsTvBearerFromUrl()`;
  - в `initGsHybridFromUrl()` сохранение токена в `window.__GS_TV_BEARER_URL` и в `localStorage` (если доступно);
  - удалено принудительное стирание `gs_tv_token` из URL;
  - в `getGsTvBearer()` добавлен приоритетный fallback: memory URL token → query token → localStorage.
- `static/agents.txt`:
  - добавлено правило про обязательный fallback токена из URL, а не только из localStorage.
- `docs/codex/2026-04-22T02-10-26_Действие_Фикс_403_tv_token_fallback.md`:
  - создан текущий аудит.

# Решения/обоснования
- Повторяющийся 403 чаще связан с тем, что клиент отправляет неверный/устаревший Bearer или теряет токен при инициализации. На части TV WebView `localStorage` работает нестабильно.
- URL `gs_tv_token` уже является частью текущего процесса pair-link, поэтому использован как безопасный практический fallback в рамках существующего контракта.
- Изменение сделано без модификации backend-правил авторизации.

# Риски
- Токен остаётся видимым в URL (если используется ссылка с `gs_tv_token`). Это повышает требования к операционной гигиене (не публиковать ссылку посторонним).
- Если сам токен в URL невалидный/просроченный, 403 сохранится; потребуется переподключение через новую ссылку pair.

# Следующие шаги
1. На проблемном устройстве открыть свежую ссылку `/screen/{slug}?gs_tv_token=...` и проверить исчезновение 403.
2. При сохранении 403 проверить статус записи в `tv_devices` (active/expired/screen_slug) на сервере.
3. Опционально: добавить серверный диагностический заголовок причины 401/403 для ускорения поддержки.
